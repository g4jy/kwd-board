# KWD 클래스룸 기획안 v1 — 판에서 교실로 (2026-10-18)

> 다음 세션(Opus 5.5)이 이 문서를 읽고 만든다. 먼저 `README.md`(v7.1까지)와 `LOOPLOG.md`를 읽을 것.
> 한 줄: 학생이 링크 하나로 들어오면 **카메라·마이크·판·녹화가 한 화면**에서 돌아가는 1:1 온라인 교실. 영상·소리는 두 사람 사이를 직접 오가고(P2P), 녹화는 **선생님 PC의 KWD 폴더에만** 남아 지금의 밤 루틴(전사·문서화·유튜브 보관)에 그대로 들어간다. 서버는 **무료 Cloudflare 워커 하나**(이미 저장소에 있음)로 충분하다.

## 0. 결론과 결정

| | 결론 | 근거 |
|---|---|---|
| 서버가 필요한가 | **있어야 한다. 단, 작은 것 하나(무료).** 영상·소리 자체는 서버를 거치지 않는다. 서버가 하는 일은 셋뿐: ① 두 브라우저를 서로 소개(시그널링) ② 판 글·필기 동기(지금 Yjs) ③ 연결이 막힌 네트워크를 위한 중계(TURN) 열쇠 발급 | 영상 통화(WebRTC)는 브라우저끼리 직접 연결하는 기술이라 '줌 서버' 같은 것이 필요 없다. 처음 소개만 해 주면 된다 |
| 어떤 서버 | **Cloudflare 워커 + Durable Object** (`server/cloudflare`, 무료 요금제로 돌아가게 이미 작성됨) + **Cloudflare Realtime TURN**(월 1,000 GB 무료, 그 뒤 GB당 $0.05) | 1:1 50분 수업 하나가 중계를 타도 약 1 GB. 한 달 100수업이 전부 중계돼도 100 GB |
| 영상 방식 | **1단계: P2P(두 사람 직접)**. 그룹 수업을 시작하면 **3단계: SFU(LiveKit)** 로 통화 모듈만 바꾼다 | 1:1은 P2P가 가장 싸고 빠르고 사생활에 좋다. 3명 이상부터 SFU가 낫다 |
| 녹화 | **선생님 브라우저가 녹화해 KWD 폴더에 바로 쓴다**(서버 녹화 없음). 영상 1개(판 영역) + 소리 2개(선생님·학생 따로) + 사건 기록(.kwd.zip) | 밤 루틴이 지금도 `<stem>_Teacher.m4a`·`<stem>_Student.m4a` 두 트랙을 쓴다. 학생 얼굴은 기본으로 녹화에 넣지 않고, 넣을지는 설정 하나 |
| 비용 | **월 0원**으로 시작 (Cloudflare 무료 + GitHub Pages). 도메인을 달면 연 1~2만 원 | 아래 5절 |
| 만드는 순서 | **0 준비(동재님 반나절) → 1 통화+녹화(핵심, 루프 2~3개) → 2 교실 다듬기 → 3 그룹·SFU → 4 브랜드·예약** | 1단계가 끝나면 바로 수업에 쓸 수 있다 |

**동재님 결정 (10/18 20:16)** — 아래 질문 1~5의 답
1. Preply 학생에게는 쓰지 않는다 (직접 학생만). 코드는 그대로, 링크를 보내지 않으면 끝.
2. 녹화에 학생 얼굴을 넣지 않는다 (선생님 얼굴도 기본 안 넣음). 녹화 = 판 + 두 사람 소리.
3. 1:1 무료(P2P)로 만든다. 그룹 수업을 시작할 때 같은 프로그램에 통화 모듈만 SFU 로 바꾼 **그룹용 교실(다른 링크)** 을 만든다.
4. 1단계는 GitHub Pages 주소 그대로, 도메인은 4단계.
5. 서버 열쇠는 동재님이 직접 넣는다(아래 0단계 순서).

**(참고) 처음 질문**

1. **Preply 학생.** Preply 규칙은 "플랫폼 밖에서 예약·결제 금지"가 핵심이고, 학생용 안내서는 접속 문제 때 Zoom·Meet 같은 다른 도구를 쓰라고까지 적혀 있다. 그래도 **튜터 규칙(Rules for tutors)에서 '수업은 Preply 교실에서'라는 조항이 있는지** 선생님 계정으로 한 번 확인. 두 길: (a) Preply 학생은 Preply Space 로 통화하고 우리 교실은 **판 + 녹화만**(카메라 꺼짐 모드) (b) 직접 학생(과제 플랫폼·kwd-app 쪽)은 우리 교실 전부. 둘 다 같은 코드다. 모드 하나 차이.
2. **녹화에 학생 얼굴을 넣을지.** 기본값 제안: **안 넣음**(판 + 두 사람 소리). 넣고 싶은 학생만 설정. 어느 쪽이든 입장 화면에 "이 수업은 복습 자료를 위해 녹화돼요" 한 줄 + 동의 단추.
3. **그룹 수업 시작 시점.** 그때 SFU로 바꾼다(3단계). 그 전에는 P2P.
4. **도메인.** `class.koreanwithdongjae.com` 같은 주소를 달지. GitHub Pages 그대로여도 동작은 같다(HTTPS 이미 됨).
5. **서버 열쇠 넣기는 동재님 손으로.** `wrangler login`, `wrangler secret put …` — 채팅에 붙여 넣지 않는다(지금 README 방식 그대로). TURN 열쇠도 Cloudflare 대시보드에서 만들어 같은 방법으로.

## 1. 지금 상태 (10/18)

- 판(v7.1)은 GitHub Pages 에 있고, 같은 기기 안에서는 창끼리 바로 동기된다(BroadcastChannel). **다른 기기·다른 나라의 학생과 같은 판을 보려면 동기 서버가 있어야 하는데, 아직 배포하지 않았다**(PC에 wrangler 로그인 흔적 없음). → 0단계 첫 일.
- 지금 수업 녹화는 화면 녹화(통화 창의 '콜 바' 기준으로 밤 루틴이 꼬리 자르기·창 전환 가리기까지 한다). 교실이 되면 **녹화가 판 영역만 깨끗하게** 나오므로 `trim_tail.py`·`mask_switches.py`·`qa_frames.py` 가 이 녹화에는 필요 없다(판 사건 기록이 시각을 다 갖고 있다).
- 학생은 24명 안팎, 1:1, 주 1회 50분, 해외(캐나다·영국·베이징 …). 폰으로 들어오는 학생도 있다.

## 2. 구조

```
학생 브라우저 ──(영상·소리: WebRTC, 직접 연결. 막히면 TURN 중계)── 선생님 브라우저(크롬)
      │                                                                  │
      └──── wss: 판 동기(Yjs) + 통화 소개(시그널) ── Cloudflare 워커(Room DO) ──┘
                                                         │ GET /rooms/<id>/turn  → 1시간짜리 TURN 열쇠 (비밀은 워커에만)
선생님 브라우저 → 녹화(탭 캡처를 판 영역으로 자름 + 소리 2트랙) → KWD 폴더 Student_Lessons/<학생>/녹화/
                                                         → 밤 루틴(ASR·문서·유튜브) 그대로
```

- **판 문서(Yjs)에는 영상·소리·시그널이 들어가지 않는다.** 시그널은 워커가 방 안의 다른 소켓에 그대로 넘기는 일회성 메시지(새 메시지 종류 하나, 예: 첫 바이트 100). 묶음(lesson_packet)은 지금처럼 PC 밖으로 안 나간다.
- **매체는 암호화(DTLS-SRTP)** 돼서 TURN 중계도 내용을 볼 수 없다. 녹화는 PC에만. 제3자 서비스에 영상이 쌓이지 않는다.

### 통화 모듈 (`src/call.ts`, 화면과 분리)

```ts
interface Call {
  join(room: string, role: 'teacher'|'student', devices: {cam?: string; mic?: string}): Promise<void>;
  leave(): void;
  local: MediaStream;            // 내 카메라·마이크
  remote(): MediaStream | null;  // 상대
  setCamera(on: boolean): void; setMic(on: boolean): void;
  stats(): { rtt: number; up: number; down: number; relayed: boolean; quality: 'good'|'ok'|'bad' };
  on(ev: 'remote'|'left'|'quality'|'error', cb): void;
}
```
1단계는 `RTCPeerConnection` 하나(P2P), 3단계는 같은 인터페이스를 LiveKit 클라이언트로 구현. 판 코드는 이 인터페이스만 본다.

- ICE: `stun:stun.cloudflare.com:3478` + 워커가 준 TURN(udp/tcp/tls 443). 연결 뒤 `relayed` 여부를 사건 기록에 남긴다(어느 학생이 늘 중계를 타는지 밤 루틴이 알게).
- 재연결: 소켓이 끊기면 3·6·12초 뒤 다시 소개(offer 재생성, ICE restart). 30초 넘으면 "다시 들어오기" 단추.
- 코덱: 기본 협상(VP8/H.264, Opus). 폰(iOS Safari)도 그대로 된다.
- 화질: 카메라 640×360 ~ 1280×720, 1~1.5 Mbps. 판은 영상이 아니라 Yjs 로 가니 대역폭이 거의 안 든다.

### 녹화 모듈 (`src/recorder.ts`, 선생님만)

1. "수업 시작"을 누르면 `getDisplayMedia({ preferCurrentTab: true, selfBrowserSurface: 'include', surfaceSwitching: 'exclude', monitorTypeSurfaces: 'exclude' })` → 크롬이 **이 탭**을 고르는 창을 한 번 띄운다(한 번 클릭).
2. `CropTarget.fromElement(stageEl)` 로 **판 영역만** 자른다(Region Capture, 크롬 104+). 그래서 오른쪽 '이 학생' 패널·목록·단추는 녹화에 안 들어간다.
3. **학생 얼굴 제외(기본):** 학생 카메라 타일은 판 영역 밖(오른쪽 카메라 기둥)에 둔다 → 잘린 영역 밖이라 녹화에 없다. 설정 "학생 얼굴도 녹화"를 켜면 타일이 판 영역 안 모서리로 들어온다. 선생님 얼굴은 설정 따로("내 얼굴 녹화", 기본 끔).
4. 소리: `AudioContext` 로 ① 내 마이크 ② 상대 소리 를 각각 `MediaStreamDestination` 에 → **MediaRecorder 세 개**: 영상+섞은 소리(webm/vp9+opus, ~2 Mbps), 선생님 소리만(webm/opus 32 kbps), 학생 소리만(동일). 1초마다 `ondataavailable` → `FileSystemWritableFileStream` 으로 **바로 디스크에**(메모리에 안 쌓음, 크롬이 죽어도 직전 1초까지 남음).
5. 파일: `Student_Lessons/<폴더>/녹화/<YYYY-MM-DD HH-MM>_#N.webm`, `…_Teacher.webm`, `…_Student.webm`, `…_rec.json`(시작 시각 = `store.now()`, 판 id, 묶음 id, 설정, 잘린 영역 크기). 기록 묶음(.kwd.zip)의 `manifest.json` 에도 같은 시작 시각 → 판 사건과 영상 시각이 1초 안에 맞는다.
6. 50분 ≈ 영상 700 MB + 소리 25 MB. 밤 루틴이 유튜브에 올리고(WebM 그대로 받음) 지우는 지금 규칙 그대로. ASR 입력은 `…_Teacher.webm`·`…_Student.webm`(필요하면 ffmpeg 로 m4a 재포장; 밤 루틴에 한 줄).
7. 폴더 없이 켠 판(체험·폴더 미연결)은 녹화 끝에 내려받기로 대신.

### 화면 (최소 원칙: 한 화면에 꼭 필요한 것 하나)

| 화면 | 보이는 것 |
|---|---|
| 학생 입장 `#/join/<판id>?t=<토큰>` | 카메라 미리보기 하나, 마이크 막대, "들어가기". 아래 작게: 카메라·마이크 고르기, "이 수업은 복습 자료를 위해 녹화돼요" (동의 = 들어가기) |
| 교실(학생) | 판 전체 + 오른쪽 위 선생님 카메라(작게) + 내 카메라(더 작게). '선생님 화면으로'·'여기 보세요'는 지금 그대로. 폰은 위에 카메라 띠, 아래 판 |
| 교실(선생님) | 지금 판 + 오른쪽 **카메라 기둥**(학생·나) + 위에 **수업 상태 칩**(연결·화질·녹화 중·경과) + 큰 단추 하나 "수업 시작" → 누르면 "끝내기" |
| 보기 모드(⋯ 또는 단축키) | ① 판 + 카메라 작게(기본) ② **카메라 크게**(판 숨김, 대화 칸에 어울림) ③ 선생님만 크게. 모드는 선생님이 바꾸면 학생도 따라간다(설정 하나로 Yjs). 녹화는 어느 모드든 **판 영역(잘린 영역)** 을 찍는다 → 카메라 크게 모드일 때는 카메라 타일이 판 영역 안으로 들어가므로 녹화에 들어간다(학생 얼굴 제외 설정이면 그때도 학생 타일만 밖) |
| 수업 시작 | 통화는 들어올 때 이미 연결. "수업 시작" = 녹화 시작 + 타이머(대화 5분) + 사건 `lesson start`. "끝내기" = 녹화 마무리 + 기록 묶음 저장 + "수업 뒤 할 일" 체크(이미 있음) |

### 시간 배분과 모드

- 오늘 탭의 칸(대화·과제 피드백·본 수업·마무리)을 누르면 타이머와 함께 **보기 모드도 제안**한다: 대화 → 카메라 크게, 나머지 → 판. 자동 전환은 하지 않는다(선생님이 누른다).

## 3. 서버 (Cloudflare 워커, `server/cloudflare`)

지금 있는 것: 방마다 Durable Object(SQLite, 무료 요금제 가능), 웹소켓으로 Yjs 동기, `/time`, 자료 그림 저장, 학생 메모리(선택). 더할 것:

| 더할 것 | 내용 |
|---|---|
| 시그널 전달 | 웹소켓 메시지 첫 바이트가 `100`이면 Yjs 에 넣지 않고 방의 다른 소켓에 그대로 전달. 방 안 소켓 수를 `/rooms/<id>/who` 로(선생님 1 + 학생 1 + 보조기기). 학생이 둘 이상 들어오면 두 번째는 거절(1:1) |
| TURN 열쇠 | `GET /rooms/<id>/turn` → Cloudflare TURN API(`TURN_KEY_ID`, `TURN_KEY_API_TOKEN` 는 `wrangler secret`)로 1시간짜리 임시 자격 → `iceServers` JSON. 판 id 가 곧 권한(지금 blobs 와 같은 규칙) |
| 입장 토큰 | 학생 링크의 `t=` 는 판 id 에서 HMAC 으로 만든 짧은 값(워커 비밀). 틀리면 소켓 거절. 선생님은 지금의 열쇠 |
| 출석 | 소켓 연결·해제 시각을 방 DO 에 기록 → `/rooms/<id>/export` 에 포함 → 기록 묶음·브리핑("학생 19:02 입장, 19:51 퇴장") |

배포: `cd server/cloudflare && npx wrangler login && npx wrangler secret put TEACHER_TOKEN && npx wrangler secret put TURN_KEY_ID && npx wrangler secret put TURN_KEY_API_TOKEN && npm run deploy`. 판의 ⋯ → 서버 주소에 `wss://kwd-board-sync.<계정>.workers.dev`.

로컬 Node 서버(`server/node`)도 같은 세 가지를 더해 시험용으로 둔다(Playwright 가 이걸로 두 브라우저 통화를 시험).

| **0. 준비** (동재님) | 워커 배포 + TURN 열쇠 + 판에 서버 주소. (선택) 도메인 | 폰(LTE)과 PC 가 같은 판을 본다 | 반나절 |

| **3. 그룹·SFU** | `call.ts` 를 LiveKit 구현으로(클라우드 무료 5,000분/월 또는 Oracle 무료 VM 자체 호스팅) · 참가자 N명 타일 · 그룹용 보기 모드 | 3~4명 수업 50분, 끊김 없이 | 루프 2 |
| **4. 브랜드·예약** | 학생마다 영원한 링크 `/s/<코드>`(오늘 방으로 자동) · 대기실 · 캘린더에서 오늘 수업 → 링크 자동 · 도메인·로고 | — | 루프 1~2 |

1단계가 끝나면 **직접 학생**과는 바로 수업할 수 있다. Preply 학생은 결정 1에 따라.

## 6. 제반 사항 점검표

**선생님 PC**
- 크롬(또는 엣지). 녹화의 탭 캡처·영역 자르기·폴더 바로 쓰기는 크롬 계열만 된다. 학생은 아무 브라우저나.
- 업로드 3 Mbps 이상, 유선 권장. 헤드셋(에코 방지 + 선생님 트랙이 깨끗해야 ASR 이 좋다).
- KWD 폴더 쓰기 허락(지금 수업필기 저장과 같은 창). 디스크 여유 20 GB.

**학생**
- 링크만. 설치 없음. 폰이면 세로 화면, 첫 화면에서 한 번 탭(소리 자동 재생 규칙).
- iOS Safari: 탭을 뒤로 보내면 카메라가 꺼진다(돌아오면 다시 켜 줌). 카카오톡 안 브라우저는 카메라가 불안정 → 입장 화면에 "브라우저로 열기" 안내.

**네트워크**
- 보통 80~90% 는 직접 연결. 회사망·일부 통신사·대칭 NAT 는 TURN 중계(자동). 사건 기록에 `relayed` 남김.
- **중국(베이징 학생):** UDP P2P 가 자주 막힌다. TURN-TCP 443 으로 시험하고, 안 되면 그 학생은 지금 도구 유지. 1단계 실제 시험 대상에 꼭 넣을 것.

**법·동의**
- 녹화 안내 + 동의(입장 화면), 개인정보 안내 페이지 한 장(무엇을 녹화하고 어디에 두고 언제 지우는지: PC + 유튜브 비공개 보관 — 지금 관행을 글로). 영국·EU·캐나다 학생은 이 한 장이 있어야 떳떳하다. 한국은 대화 당사자 녹음 합법.
- 미성년 학생(베이징 9학년 등)은 보호자 동의 한 줄을 Preply 메시지로.
- Preply: 결정 1.

**사생활**
- 영상은 암호화돼 두 브라우저 사이만. 서버·중계는 내용을 못 본다. 녹화·묶음·메모리는 PC. 학생 기기로는 판 글·필기만(지금 규칙).

**실패 대비**
- 통화가 안 되면 지금처럼 Preply/Zoom 으로 소리만 하고 교실은 판 + 녹화(카메라 꺼짐 모드)로. 교실이 통째로 안 열리면 판 v7.1 그대로.

## 7. 시험 (만들 때 반드시)

- Playwright 두 컨텍스트(`--use-fake-device-for-media-stream`, `--use-fake-ui-for-media-stream`) + 로컬 Node 서버: 입장 → 서로 영상 수신(원격 `<video>` 의 `videoWidth > 0`) → 녹화 10초 → 파일 3개 크기 > 0, `rec.json` 시각이 manifest 와 1초 안 → 끊고 재연결 → 학생 둘째 거절.
- 크롬 실제: 동재님 PC ↔ 폰(LTE, 와이파이 끔) 10분. 베이징 학생 1회 시험.
- 체험(#/demo)에는 **가짜 상대**(녹화된 짧은 영상이 '학생 카메라'로 나오는 모드)를 넣어, 서버 없이도 교실 화면을 눌러 볼 수 있게 한다.

## 8. 만들지 않는 것 (지금은)

- 서버 쪽 녹화, 화면 공유(판 안에 사진·영상·유튜브·학습지가 다 들어가므로), 채팅창(판 글상자가 있음), 가상 배경, 녹화 편집, 자동 자막(밤 루틴 ASR 이 함).


## 9. 만든 것 (v8, 10/18 밤)

- `src/call.ts` — 1:1 P2P 통화. 소개(시그널)는 **Yjs awareness**로 한다(서버를 바꿀 필요 없음, 같은 브라우저 창끼리도 됨). 선생님이 묻고(offer) 학생이 답한다(answer), 후보는 모아서 한 번에. 끊기면 3·6·12초 뒤 다시. 상태: 연결 좋음/느림/나쁨 · 지연 · 중계 여부.
- `src/lessonrec.ts` — 녹화. 크롬 '이 탭' 캡처 → **요소 캡처(RestrictionTarget)로 판(.stage)만** (카메라 칸·패널·단추 빠짐, 안 되면 영역 자르기) + 소리 3줄(섞은 것·선생님만·학생만) → KWD 폴더 `Student_Lessons/<학생>/녹화/<날짜 시각>_#N(.webm|_Teacher.webm|_Student.webm|_rec.json)`. 폴더가 없으면 끝날 때 내려받기.
- `src/classroom.ts` — 카메라 칸(오른쪽 위) · 마이크/카메라 끄기 · 얼굴 크게(학생도 같이) · 학생 입장 화면(선생님이 카메라를 켜야 뜬다, 미리보기·마이크 막대·녹화 안내) · 수업 시작 → `● 녹화 12:34 · 끝내기`(두 번 눌러 끝) → 녹화 저장 + 기록 묶음(.kwd.zip, manifest 에 `recording`).
- 서버: 워커·로컬 서버에 `GET /turn?room=` (워커는 Cloudflare TURN 임시 열쇠, 4시간).
- 체험(#/demo/split)은 가짜 카메라(그림)로 선생님·학생이 실제로 연결된다.
- 시험: `scripts/v8-smoke.mjs` (가짜 카메라 두 브라우저, 녹화 파일 4개 확인).

**아직 (2단계에서):** 입장 토큰(지금은 판 id = 권한), 기기 고르기, 출석 → 브리핑, 밤 루틴이 `녹화/`를 읽는 일(지시문 24-A12), 실제 기기 시험(PC ↔ 폰 LTE, 베이징).

## 10. 0단계 — 동재님이 할 일 (한 번만)

1. Cloudflare 계정(무료)으로 로그인 → 대시보드 **Realtime → TURN** 에서 TURN 키 하나 만들기 → 키 ID 와 API 토큰을 메모장에만 잠깐.
2. PC 에서:
   ```
   cd C:\KWD\work\kwd-board\server\cloudflare
   npm install
   npx wrangler login
   npx wrangler secret put TEACHER_TOKEN        (선생님 열쇠 — 아무 긴 글자)
   npx wrangler secret put TURN_KEY_ID          (1의 키 ID)
   npx wrangler secret put TURN_KEY_API_TOKEN   (1의 API 토큰)
   npm run deploy
   ```
   마지막 줄에 나오는 `https://kwd-board-sync.<계정>.workers.dev` 를 기억.
3. 판 ⋯ → 서버·선생님 열쇠 → 주소에 `wss://kwd-board-sync.<계정>.workers.dev`, 열쇠에 2의 선생님 열쇠.
4. 확인: 판 칩 → 학생 링크를 폰(와이파이 끄고 LTE)에서 열기 → PC 에서 '카메라 켜기' → 폰에 입장 화면 → 들어가기 → 서로 보이면 끝.

## 11. v8.1 (10/19) — 언제든 시작
- 학생 고정 링크 `#/c/<교실 코드>`: 학생마다 한 번 만든 무작위 코드(k+8자, 이 PC localStorage + 학생 폴더 `kwd-board/classroom.json`). 그날 판 = `<코드>d<수업일>`, 수업일은 서울 새벽 4시 기준.
- 배포본(github.io)은 서버 주소가 기본값 → 주소 입력 없음. 선생님 열쇠만 PC에 한 번.
- 학생: 링크로 들어오면 바로 입장 화면(들어가기 / 카메라 없이 / 판만 볼게요). 판만 보다가 카메라 칸의 '카메라 켜기'.
- 선생님: 학생이 카메라를 켜고 들어오면 선생님 카메라가 저절로(이 PC에서 허용해 둔 뒤). 아니면 '카메라 켜기'가 깜빡임.
- 설치형: manifest + 아이콘 → 크롬 '앱 설치'로 바탕화면 아이콘.

## 12. v8.2 (10/19) — 카메라 배치 · 소리 줄 분리 · 수업 폴더 자동 저장
- 카메라 칸: 끌어서 옮기기, 오른쪽 아래 모서리로 크기, '배치' → 겹쳐 보기 / 위아래 / 나란히 / 내 화면 숨기기 / 처음대로. 기기마다 따로 저장(상대 화면은 안 바뀜). '얼굴 크게'는 그대로 선생님이 바꾸면 둘 다.
- 녹화 소리 4줄: 영상(선생님 + 탭 소리) · _Teacher(마이크만) · _Student(학생만) · _Media(판에 올린 영상·소리 파일만). 모든 줄은 같은 시각에 시작(무음으로 이어짐).
- 유튜브는 다른 사이트라 소리만 뺄 수 없음 → _rec.json(kwd-lesson-rec/v2) `media` 에 재생 구간 {kind, name, ref(영상 id), from_s, to_s}. 판 사건 기록에도 media:play/stop.
- 저장: 수업마다 새 폴더 `Student_Lessons/<학생>/녹화/<YYYY-MM-DD HH-mm>/` (겹치면 ' (2)'). 녹화 4줄 + _rec.json + 판 기록 .kwd.zip 을 묻지 않고. 학생 폴더 없이 연 판은 `Student_Lessons/_수업녹화/<판>/…`. KWD 폴더 연결이 없을 때만 내려받기.
- 밤 루틴(24-A12): 녹화/<수업>/ 폴더 단위로 읽고, _Teacher·_Student 를 전사, media 구간은 '[자료/유튜브 재생]'으로 표시.
